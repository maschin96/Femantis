# GitHub-Prüfungen (Issue #5)

`.github/workflows/quality.yml` startet für Pull Requests und Änderungen an `main`. Der öffentliche Frontend-Job führt auf Ubuntu 24.04 mit Node 22 `npm ci` und `npm run build` einschließlich Typprüfung aus. Für interne PR-Branches und `main` laufen danach drei Ubuntu-Jobs mit Python 3.11, 3.12 und 3.13: Sie installieren den in `scripts/setup_backend.py` festgelegten privaten Toolbox-Commit und führen `npm run test:backend` und `npm test` aus. Das Setup-Skript wendet `backend/constraints.txt` bei Python 3.13 an. Ein separater macOS-15-Job baut die Anwendung und startet `npm run test:desktop` mit echtem Electron/WebGL; bei Fehlern werden Playwrights `test-results/` für sieben Tage als Artefakt gespeichert.

Die Repository-Administration muss das Actions-Secret `TOOLBOX_READ_TOKEN` bereitstellen: ein dedizierter, möglichst kurzlebiger Fine-grained-PAT mit **Contents: Read-only** ausschließlich für `maschin96/FEM-Toolbox`. Das Secret ist nur während der Installation der Toolbox im betreffenden Schritt sichtbar. Fehlt es, meldet der Job einen klaren Fehler. Fremde Fork-PRs erhalten dieses Secret nicht; dort läuft nur die Frontend-Prüfung. Die Workflow-Berechtigung `contents: read` gilt für den `GITHUB_TOKEN`; es gibt kein `pull_request_target`. Externe Actions sind auf vollständige Commit-SHAs fixiert. Die Desktop-Artefakte sind nur Fehlerdiagnostik und dürfen keine Zugangsdaten enthalten.

Ein grüner Frontend-Job allein belegt weder die Backend- noch die Desktopprüfung. Für einen integrierbaren internen PR müssen die drei Python-Jobs und der macOS-Job ebenfalls grün sein. Branch Protection ist eine separate Repository-Einstellung und derzeit nicht belegt. Die GitHub-API verweigerte am 14.10.2026 die Prüfung der Protection-Einstellung mit HTTP 403 und verwies auf einen erforderlichen Pro-Tarif bzw. ein öffentliches Repository.

**Beobachteter PR-Lauf vom 14.10.2026:** [Quality-Run 38524756622](https://github.com/maschin96/Firmantis/actions/runs/38524756622) startete keinen Runner. Der Frontend-Check erhielt die GitHub-Annotation „The job was not started because recent account payments have failed or your spending limit needs to be increased“. Backend und Desktop wurden danach übersprungen. Diese Kontosperre muss in GitHub Billing/Plans behoben werden; erst anschließend können Runner-Eignung und Tests am PR und danach auf `main` nachgewiesen werden. Das noch fehlende `TOOLBOX_READ_TOKEN` ist ein zweiter, unabhängiger Blocker für die privaten Jobs.
