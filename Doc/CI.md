# GitHub-Prüfungen (Issue #5)

`.github/workflows/quality.yml` startet für Pull Requests und Änderungen an `main`. Der öffentliche Frontend-Job führt auf Ubuntu 24.04 mit Node 22 `npm ci` und `npm run build` einschließlich Typprüfung aus. Für interne PR-Branches und `main` laufen danach drei Ubuntu-Jobs mit Python 3.11, 3.12 und 3.13: Sie installieren den in `scripts/setup_backend.py` festgelegten Commit der öffentlichen Toolbox ohne Zugangsdaten und führen `npm run test:backend` und `npm test` aus. Das Setup-Skript wendet `backend/constraints.txt` bei Python 3.13 an. Ein separater macOS-15-Job baut die Anwendung und startet `npm run test:desktop` mit echtem Electron/WebGL; bei Fehlern werden Playwrights `test-results/` für sieben Tage als Artefakt gespeichert.

Seit dem 19.10.2026 sind `maschin96/FEM-Toolbox` und dieses Repository öffentlich. Der Workflow verwendet keine Secrets; das frühere `TOOLBOX_READ_TOKEN` ist entfallen und kann, falls angelegt, gelöscht werden. Backend- und Desktopjobs laufen weiterhin nur für Branches dieses Repositorys und `main`; für fremde Fork-PRs läuft nur die Frontend-Prüfung. Ob auch Fork-Code auf den Backend- und macOS-Runnern laufen soll, ist eine separate Entscheidung. Die Workflow-Berechtigung `contents: read` gilt für den `GITHUB_TOKEN`; es gibt kein `pull_request_target`. Externe Actions sind auf vollständige Commit-SHAs fixiert. Die Desktop-Artefakte sind nur Fehlerdiagnostik und dürfen keine Zugangsdaten enthalten.

Ein grüner Frontend-Job allein belegt weder die Backend- noch die Desktopprüfung. Für einen integrierbaren internen PR müssen die drei Python-Jobs und der macOS-Job ebenfalls grün sein. Branch Protection ist eine separate Repository-Einstellung. Am 14.10.2026 verweigerte die GitHub-API die Abfrage für das damals private Repository mit HTTP 403; am 19.10.2026 meldete sie für `main` „Branch not protected“ (HTTP 404). Erforderliche Checks werden also derzeit nicht erzwungen.

**Beobachteter PR-Lauf vom 14.10.2026:** [Quality-Run 38524756622](https://github.com/maschin96/Firmantis/actions/runs/38524756622) startete keinen Runner. Der Frontend-Check erhielt die GitHub-Annotation „The job was not started because recent account payments have failed or your spending limit needs to be increased“. Backend und Desktop wurden danach übersprungen. Diese Kontosperre muss in GitHub Billing/Plans behoben werden; erst anschließend können Runner-Eignung und Tests am PR und danach auf `main` nachgewiesen werden. Der damals zusätzlich fehlende Toolbox-Lesezugriff ist seit der Veröffentlichung der Toolbox kein Blocker mehr.
